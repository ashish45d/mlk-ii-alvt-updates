## 2. Executive Summary

This Tool Classification Report (TCR) defines the safety-critical classification of the MLK-II ALVT Logic to CAD Converter Tool. In accordance with railway software safety standard **CENELEC EN 50128:2011 (Section 6.7)**, engineering design and verification support tools must be formally classified and qualified to ensure they do not introduce silent errors into signaling interlocking designs.

This report evaluates the functional impact of the logic converter and justifies its classification as a **Class T2 Tool**.

---

## 3. Tool Description & Scope

The MLK-II ALVT Tool translates compiled Microlok logic source code into structured AutoCAD drawing files (`.dxf`) and consolidated PDF schematic sets.

The scope of this safety classification is limited strictly to the drawing generation sub-systems:
*   **Standard Logic to CAD (Black & White layout rendering)**
*   **Logic Differential CAD (Red & Green layout rendering)**

*All other utilities in the ALVT suite (such as diagnostic datalogger analysis or text editors) are excluded from the vital safety scope and operate under Class T1.*

---

## 4. Software Tool Classification Analysis

### 4.1 Safety Tool Classes defined in EN 50128
CENELEC EN 50128 defines three tool classes based on their potential to introduce or fail to detect errors:

*   **Class T1**: Generates no outputs which can directly or indirectly influence the safety-critical design (e.g. code formatting checkers, text editors).
*   **Class T2**: Supports the design, test, or verification of the system where errors in the tool's output could fail to detect a fault, but **cannot directly introduce safety faults** because the output is subject to subsequent manual review/verification.
*   **Class T3**: Generates output that directly becomes part of the safety-critical system without manual verification (e.g. safety code compilers, code generators).

---

### 4.2 Hazard & Impact Analysis

The following table evaluates potential tool malfunctions and their safety impacts:

| Potential Tool Malfunction | Consequence | Mitigation Mechanism |
| :--- | :--- | :--- |
| **Omission of a Contact** | A contact in a logic rung is missing from the schematic drawing, misrepresenting the code. | **Manual Verification**: The checker cross-references the drawing contacts with the text equations in the source `.txt` file. |
| **Incorrect Logic Operator (Series vs Parallel)** | Rungs are drawn in parallel instead of series, showing a logical bypass. | **Signaling Test Check**: The testing team performs functional checks on the physical interlocking using the drawings. |
| **Incorrect Diff Highlighting (Red/Green)** | An added or deleted contact is highlighted as unchanged (false negative). | **Text-based Reconciliation**: The checker reconciles all drawing highlights with the generated text diff report (`*_diff_report.txt`). |
| **Stale Sheet Insertion** | An old sheet from a previous compilation run is inserted into the final PDF bundle. | **Page Validation**: Checkers inspect page numbers against the Drawing Index sheet page counts. |

---

### 4.3 Classification Justification

The MLK-II ALVT Converter is formally classified as a **Class T2 Tool** because:
1.  **Independent Review**: The CAD drawings and diff reports generated by the tool are used as verification and audit drawings. They are subject to a **complete manual review** by a design verifier and independent checker.
2.  **No Code Injection**: The tool does not write, compile, or inject executable code into the vital interlocking CPU. The vital software execution is governed entirely by the Microlok compiler.
3.  **No Direct Vital Impact**: A failure in the tool’s layout engine may cause a drawing representation error but cannot directly cause an unsafe interlocking state on the railway line, as the vital interlocking execution remains unchanged.

---

## 5. Conclusion & Qualification Requirement

Based on the safety analysis, the MLK-II ALVT Logic to CAD Converter is qualified as a **Class T2 Tool**. 

To satisfy the safety audit requirements of the Independent Safety Assessor (ISA), the following verification tasks must be completed:
*   **Tool Validation Plan & Report (TVP/TVR)** containing structured test cases and regression execution results.
*   **Safety Audit Rules** embedded in the User Manual to govern the checker's verification steps.
